# AI 협업 정책 및 지식 계층 설계

> **핵심 한 줄**: AI(Claude Code) 활용 방식과 프로젝트 지식 계층을 명시적으로 설계한 흔적을 남긴다. "이미 검토했다"는 사실 자체가 다음 의사결정의 출발점이 된다.

---

## 1. 왜 이 문서가 있는가

코드·아키텍처만 정리하면 프로젝트가 "기술적으로" 완성될 뿐이다. **AI를 어떻게 활용할지에 대한 명시적 설계**까지 포함되어야 운영·확장 단계에서 흔들리지 않는다.

이 문서는 다음을 기록한다:
- 현재 채택한 지식 계층(왜 이렇게 나눴는가)
- 검토했지만 **보류한** 도입 항목과 그 근거
- 재검토 트리거 조건

---

## 2. 현재 지식 계층 (3-Layer)

| 계층 | 위치 | 로드 시점 | 책임 |
|------|------|-----------|------|
| **즉시 로드** | [/CLAUDE.md](../CLAUDE.md) | 매 세션 자동 | 프로젝트 전반 규칙·금기·문서 우선순위 |
| **참조** | [/docs/*.md](.) | 필요 시 Claude가 읽음 | 아키텍처·작업 일지·비교 지식·운영 패턴 |
| **자동(개인)** | `~/.claude/.../memory/` | 대화 간 자동 회상 | 사용자 선호·피드백 (대화 누적) |

### 설계 의도
- **CLAUDE.md는 짧게** — "정책·금기"만. 코드 컨벤션은 코드 자체가 진실이므로 적지 않는다.
- **docs/는 사람과 AI가 같이 본다** — AI 전용이 아닌 일반 문서. AI는 CLAUDE.md의 우선순위 안내를 따라 진입한다.
- **memory/는 자동** — 사용자가 직접 관리하지 않는다. Claude가 대화 중 학습한 선호만 누적.

### 계층 분리 원칙
"코드를 읽으면 알 수 있는 것은 어디에도 적지 않는다." 들여쓰기·네이밍·import 순서는 모두 코드가 진실. 문서는 **숨겨진 제약·외부 정책·표준 정합성 갭**처럼 코드만 봐서는 알 수 없는 것만 담는다.

## 3. Second Brain — 검토 결과: **보류**

> 검토 일자: 2026-04-28

### 3.1 검토 배경
프로젝트 규모가 커지고 외부 지식(SyncML 스펙·OMA-DM 사례 등)을 축적할 가능성이 보임. "별도 지식 베이스(Second Brain)를 둘 것인가"를 검토함.

### 3.2 보류 근거
| 항목 | 현재 상태 |
|------|-----------|
| 문서 수 | 5개 (탐색 비용 낮음) |
| 개발자 수 | 1인 (정보 동기화 비용 낮음) |
| 도메인 수 | 단일 (SyncML OTA) |
| 외부 자료 누적 | 없음 |
| ADR(의사결정 기록) 필요성 | 아직 ARCHITECTURE.md에 녹아 충분 |

→ 현재 3-Layer로 커버 가능. 별도 계층은 **빈 폴더 + 사용 안 하는 템플릿**만 남길 위험.

### 3.3 재검토 트리거 (다음 중 **2개 이상** 해당 시)
1. **다중 프로젝트 지식 공유** — 다른 OTA/SyncML 프로젝트와 노하우 교차 참조 필요
2. **ADR 필요성 대두** — "큐 RabbitMQ → Kafka 전환?" 같은 큰 결정의 이력이 코드/아키텍처 문서에 안 들어감
3. **외부 참여자 증가** — 신규 합류자 온보딩, PM/QA의 활발한 참조
4. **외부 자료 누적** — SyncML 1.2 발췌·OMA-DM 사례·RabbitMQ 패턴 등 "정리된 외부 지식"이 쌓이기 시작
5. **검색 한계** — `docs/`가 20개 이상이 되어 grep만으로는 못 찾음

### 3.4 도입 시 가장 가벼운 형태 (별도 도구 없이)
```
docs/
├── (기존 문서들)
└── KNOWLEDGE/
    ├── syncml-1.2-notes.md   # 스펙 발췌·해석
    ├── oma-dm-cases.md        # 다른 OTA 시스템 사례
    └── decisions/             # ADR
        └── 0001-queue-choice.md
```
- Obsidian/Notion/Logseq 등 외부 도구 도입은 **이 단계 다음** 검토.
- 도입 시 [/CLAUDE.md](../CLAUDE.md) 문서 우선순위에 추가.
